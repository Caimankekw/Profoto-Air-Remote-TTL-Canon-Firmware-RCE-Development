# C11 地址变换参考数据

[English](README.md) | 开发者：Caimankekw

`c11_offset_transform.bin` 是离线分析原 C11 更新器使用的派生字节变换参数，不含设备序列号、USB 路径、原始事务日志、设备备份或原厂明文镜像。原固件和更新器保留各自权利，见 [NOTICE](../NOTICE.md)。

支持的 PIC18 字节地址范围严格为 `[0x4002, 0x10000)`。文件共 **73,725 字节**，前 **49,150 字节**为 XOR 参数，后 **24,575 字节**为打包掩码；低半字节对应较小地址，高半字节对应下一个地址。文件无头部，格式、范围和下列 SHA-256 由 `codec_manifest.json` 及工具常量固定：

```text
7779d34181f9d302d2d122e9a2ed40f975a4128b738a40561f97fc86ac949303
```

设明文字节为 `p`、XOR 参数为 `k`、四位掩码为 `m`：

```text
t = (p XOR (p >> 4)) AND m AND 0x0F
swap(p, m) = p XOR t XOR (t << 4)
encode(p) = swap(p, m) XOR k
decode(c) = swap(c XOR k, m)
```

变换不移动字节地址。每个掩码位决定是否交换同一字节中相隔四位的一对位，因此 `swap` 是自身的逆运算。参数来自固定填充/指令参考，其原始事务与设备元数据不随仓库分发。

`tools/reference_codec.py` 只使用 Python 标准库；通用内存接口 `encode`、`decode`、`encode_patch` 均拒绝范围外请求。这些接口不是更新器，也不是 P8 补丁实现。

`decode_original_bytes()` 只接受指纹固定的原 C11 应用传输区，返回基址 `0x4000`、长度 113,664 字节的分析表示及已知字节掩码。`0x4000–0x4001` 仍未知：明文零占位、掩码为零，不能当作恢复出的指令。固定原程序在 `[0x10000, 0x1FC00)` 的已确认 `FF` 尾部，仅在完整原传输哈希匹配后补齐；不宣称具有该尾部或 boot/config 区的通用解码能力。此分析表示不可作为直接刷写文件。

`codec_equivalence.json` 保留已有逐地址等价比较及原镜像/掩码哈希证据，仅为证据元数据，并非运行依赖。独立[测试](../tests/README.zh-CN.md)无需设备或原厂 EXE 即可检查参数和变换，但不证明硬件、无线或光学行为。
