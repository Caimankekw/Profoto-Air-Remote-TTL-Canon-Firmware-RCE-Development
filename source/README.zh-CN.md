# AIR2-P8-FIX1 构建源码

[English](README.md) | 简体中文

Caimankekw 原创的 PIC18 补丁汇编器与链接器采用 AGPL-3.0-only。它们不是 Profoto 原厂 C 源码，也没有替代完整原厂应用程序。原厂指令与其他第三方材料保留各自权利，见[许可范围](../NOTICE.zh-CN.md)。构建命令见[仓库 README](../README.zh-CN.md)。

| 文件 | 职责 |
| --- | --- |
| `hss_patch.py` | 从源码及原 C11 算术代码构建现有 HSS 适配。 |
| `ui_patch.py` | 六组 UI、按键处理和 FIX1 的 AIR1 空闲到期事务处理。 |
| `radio_patch.py` | 根据六组内部状态生成目标功率与开关指令。 |
| `persistence_patch.py` | V4 设置日志及旧记录格式迁移。 |
| `linker.py` | 两遍解析组件调用，保护 HSS、原生区域与保留参数页。 |
| `PROVENANCE.json` | 原创源码哈希与独立构建迁移说明。 |

FIX1 在忙时保留已到期的原生 AIR1 期限，在一次成功的就绪路径中消费期限并清除六组相对值。它未增加 RAM 或调整定时周期。无线与持久化组件字节及 HSS-P3 保护区保持不变。

`build.py` 只读取显式指定的原厂 C11 EXE 和本仓库文件，通过 `reference/` 参数解码受支持区域，从源码生成 HSS-P1 并修正头部校验，再链接 P8-FIX1 组件。它不读取预构建 P1/P3 镜像、P3 更新器、设备备份、恢复采集记录或冻结 P8 补丁配方。封装配方在源码构建**之后**生成，再独立重放以检查封装。

冻结输出哈希是发布检查条件。修改源码导致输出变化时检查会失败；发布其他版本需要独立验证和新的预期哈希。成功复现不等于验证了硬件、射频或物理时序。FIX1 尚未进行实机启动或相机测试。

partial BIN 的首字仍是未知占位，**不能直接刷写**。封装保留原始编码首字、尾部、配置和内嵌固件资源以外的字节。C11 头部校验公式覆盖 `0x4002..0x4100`，排除 `0x4050..0x4052`；这不代表已经恢复所有引导程序完整性检查机制。
